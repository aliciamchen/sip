# Experiment structure

Each experiment folder contains:
- `index.html` - entry point (byte-identical across experiments; generated by `experiments/sync_entry_files.py`)
- `experiment.js` - thin call to `runExperiment()` from `_lib/bootstrap.js` (also generated by `sync_entry_files.py`)
- `trials.js` - only the study-specific `makeStimulusTrials`; exports `CONFIG` (via `makeConfig("<slug>")`), `INSTRUCTIONS_PAGES` (via `STUDY_INSTRUCTIONS["<slug>"]`), and `makeStimulusTrials`

Most of each experiment is shared `_lib/` modules; `trials.js` just composes them:
- `bootstrap.js` — `runExperiment({ config, makeStimulusTrials, instructionsPages, consentTemplate })` assembles the whole timeline (consent → instructions → stimulus trials → exit survey → save → thank-you). Timeline-wide changes go here, not in `trials.js`.
- `config.js` — `DATAPIPE_IDS` + shared `SHARED_CONFIG`; `makeConfig("<slug>")` merges them.
- `instructions.js` — `STUDY_INSTRUCTIONS` (all four studies' instruction pages in one place).
- `scenario.js` — per-trial building blocks (`getDesireText`/`getEffortText`, `intimacyDescriptor`, slider labels, `pressAnyKeyPage`, `blankPause`, `scenarioStimulus`).
- `two-slider.js` — `makeTwoSliderForm(...)` (two sliders on one page, Studies 1b/2b).
- `timeline.js`, `attention-check.js`, `memory-checks.js`, `style.css`, `consent/` — remaining boilerplate.

Each experiment references `_lib/` via `../_lib/`, so the active experiments are not standalone folders — `_lib/` must be deployed alongside them.

Experiments collect data via jsPsych-contrib/pipe plugin to `data/<experiment_name>/raw_data/`.

Config repeated across experiments is collected in [`experiments/_lib/config.js`](../../experiments/_lib/config.js): the `DATAPIPE_IDS` map (each experiment needs its own DataPipe ID — keyed by slug), the shared Prolific completion link, and the attention-check index/tolerance and inter-trial durations. Each `trials.js` calls `makeConfig("<slug>")` to merge the shared defaults with that experiment's DataPipe ID, passing overrides as a second argument when it needs to depart from a default.

## Deploy

Deploys go through [`bin/deploy-experiment`](../../bin/deploy-experiment), which rsyncs an experiment + `_lib/` to athena (`~/www/sip/experiments/`). Usage: `bin/deploy-experiment <slug>`. The script only accepts the four active slugs (Makefile's `EXPERIMENTS_INVERSE`): `food_inv_desire`, `food_inv_joint_de`, `food_inv_intimacy`, `food_inv_joint_ie`. See [experiments/README.md](../../experiments/README.md#deploying-experiments) for the full reference.

## Scenario CSVs are generated from Python

The scenario CSVs are generated artifacts. Their source of truth is the corresponding `.py` file, which holds the scenario data as Python dicts and writes the CSV when run. Edit the `.py` file and regenerate with `uv run python experiments/<file>.py` — never edit the CSVs directly, since the next regeneration will overwrite the edits. The active set is `experiments/scenarios.py` → `scenarios.csv` (3-action). The earlier sets are archived under `experiments/legacy/`: `scenarios.py` (4-action canonical), `scenarios_effort.py` (2-action), `scenarios_nonfood.py` (non-food).

`scenarios.csv` is the 3-action canonical set for the inverse-planning experiments (Studies 1a, 1b, 2a, 2b). It carries the low_risk_share_effort_low/low_risk_share_effort_high paragraphs alongside the desire and intimacy framing so all three latent variables — desire, effort, intimacy — can be manipulated alongside the observed action. The three action columns are `no_share` / `low_risk_share` / `high_risk_share` (renamed from `action_0`/`1`/`2` in the May 2026 cleanup). (It was `scenarios_3act.csv` until the May 2026 cleanup renamed it to `scenarios.csv` and moved the older 4-action/2-action/non-food sets to `experiments/legacy/`.)

Each experiment directory also has a per-experiment `json/stimuli.json` that is generated from one of the scenario CSVs. The routing from CSV to experiment dirs is in `experiments/csv_to_json.py` — run that after editing any scenario `.py` file to propagate changes into the experiments that consume it.
