# nonfood_inv_joint_de

Study 3a — Joint inference over desire and effort, given intimacy, on the nonfood scenario set.

## Design

This study is Study 1b's design (`food_inv_joint_de`) run on the 16 nonfood scenarios, which span bodily-substance transfer, shared physical exposure, and private access instead of food sharing.

**Factor crossing**: 4 (intimacy: max_formal/somewhat_formal/somewhat_intimate/max_intimate) × 3 (observed action)

**Known to participant**: intimacy_condition

**Inferred by participant**: desire_condition AND effort_condition (two sliders per trial — a continuous 0–100 desire slider with "not at all" / "extremely" endpoints, and an effort slider with low_risk_share_effort_low/high paragraph endpoints)

## Trial structure

Each trial shows: intimacy-descriptor preamble page, then vignette + observed action (at posterior). Neither desire nor effort paragraph is shown in the vignette.

Slider responses: both sliders appear on one page per phase (a prior page and a posterior page), rendered via `survey-html-form` (see `_lib/two-slider.js`) since the `html-slider-response` plugin only supports one slider per trial. The desire slider asks about the scenario's own `desire_object` (e.g. "the chapstick", "to try the harmonica"); the effort slider uses the low_risk_share_effort_low/high paragraph endpoints. Each phase records one trial whose `response` is an object keyed by slider, `{desire, effort}`. The Continue button stays disabled until both sliders are moved.

Each participant sees 16 trials (one per scenario) with cells balanced across participants. Cell space: 12 cells. The shared counterbalancing generator (`experiments/build/counterbalancing.py`) produces 240 sequences (15 rounds × 16 rotations), each a 16-trial assignment of factor cells to the 16 scenarios.

The memory checks come from `NONFOOD_MEMORY_CHECKS` (sleeping-bag + salary; three questions total), and the consent template is the domain-general `_lib/consent/nonfood-inverse.html`.

## Stimulus source

Loads stimuli from `experiments/scenarios_nonfood.csv` via the routing in `experiments/build/csv_to_json.py`. Regenerate `json/stimuli.json` with:

```bash
uv run python experiments/build/csv_to_json.py
```

## Files in this directory

- `index.html`, `experiment.js` — generated entry files written by `experiments/build/sync_entry_files.py`; do not edit by hand. `experiment.js` is a thin shim that hands this study's exports from `trials.js` to `runExperiment(...)` in `../_lib/bootstrap.js`, which fetches the assets, assigns the counterbalancing sequence (spreading each sequence item's factor fields onto its stimulus), and assembles the full timeline (consent → instructions + comprehension gate → stimulus trials → exit survey → save → thank-you).
- `trials.js` — the study-specific code: its `CONFIG`, its instruction and comprehension-check selections, and `makeStimulusTrials(...)` (scenario presentation, sliders, and attention/memory-check placement), composed from the shared modules in `../_lib/`.
- `json/stimuli.json` — generated from `scenarios_nonfood.csv`; do not edit by hand
- `json/full_counterbalancing.json` — generated by `experiments/build/counterbalancing.py`; one sequence per condition_assignment

## Before running pilots

- Set this experiment's DataPipe experiment ID and Prolific completion code in `experiments/_lib/config.js` (the `DATAPIPE_IDS` and `PROLIFIC_COMPLETION_CODES` maps, keyed by slug). The experiment refuses to start until both are set.
- Open `index.html` locally and walk through a few trials per cell to confirm the UI renders and the slider endpoints / observed actions look right.
