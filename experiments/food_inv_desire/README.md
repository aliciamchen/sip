# food_inv_desire

Study 1a — Desire inference.

## Design

**Factor crossing**: 2 (effort: low/high) × 4 (intimacy: max_formal/somewhat_formal/somewhat_intimate/max_intimate) × 3 (observed action)

**Known to participant**: effort_condition, intimacy_condition

**Inferred by participant**: desire_condition (one continuous 0–100 slider — "how much do they want to eat the food?", endpoints "not at all" / "extremely"). The desire_low/desire_high paragraphs are not shown.

## Trial structure

Each trial shows: intimacy-descriptor preamble page, then vignette + effort paragraph + observed action (at posterior). The desire paragraph is hidden, since desire is the target of inference.

Slider responses: one continuous slider (0–100, endpoints "not at all" / "extremely"), rating "how much do {name_0} and {name_1} want to eat the food?" with the scenario's two character names.

Each participant sees 16 trials (one per scenario) with cells balanced across participants. Cell space: 24 cells (each participant samples 16 of 24). The shared counterbalancing generator (`experiments/build/counterbalancing.py`) produces 480 sequences (30 rounds × 16 rotations), each a 16-trial assignment of factor cells to the 16 scenarios.

The trial flow follows the "noalt" pattern: no candidate action list shown to the participant, only the single observed action at the posterior stage. The participant sees an intimacy-descriptor preamble page first (since intimacy is a known frame for this study), then the prior slider.

## Stimulus source

Loads stimuli from `experiments/scenarios.csv` via the routing in `experiments/build/csv_to_json.py`. Regenerate `json/stimuli.json` with:

```bash
uv run python experiments/build/csv_to_json.py
```

## Files in this directory

- `index.html`, `experiment.js` — generated entry files written by `experiments/build/sync_entry_files.py`; do not edit by hand. `experiment.js` is a thin shim that hands this study's exports from `trials.js` to `runExperiment(...)` in `../_lib/bootstrap.js`, which fetches the assets, assigns the counterbalancing sequence (spreading each sequence item's factor fields onto its stimulus), and assembles the full timeline (consent → instructions + comprehension gate → stimulus trials → exit survey → save → thank-you).
- `trials.js` — the study-specific code: its `CONFIG`, its instruction and comprehension-check selections, and `makeStimulusTrials(...)` (scenario presentation, sliders, and attention/memory-check placement), composed from the shared modules in `../_lib/`.
- `json/stimuli.json` — generated from `scenarios.csv`; do not edit by hand
- `json/full_counterbalancing.json` — generated by `experiments/build/counterbalancing.py`; one sequence per condition_assignment

## Before running pilots

- This experiment's DataPipe experiment ID and Prolific completion code are already set in `experiments/_lib/config.js` (the `DATAPIPE_IDS` and `PROLIFIC_COMPLETION_CODES` maps, keyed by slug).
- Open `index.html` locally and walk through a few trials per cell to confirm the UI renders and the slider endpoints / observed actions look right.
